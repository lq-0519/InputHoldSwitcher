# InputHoldSwitcher · 豆包语音自动切回输入法

用豆包输入法长按快捷键进行语音输入后，自动切回平时使用的输入法，省去每次说完话都手动切换的操作。

适合“语音使用豆包，键盘打字使用微信输入法或其他输入法”的场景。豆包负责唤起语音和识别，本工具负责在松开按键后切回。

## 工作流程

1. 按住触发键，例如左 Control，豆包输入法切入并开始语音识别。
2. 松开按键，本工具等待设置的延迟。
3. 延迟到期后，若仍在敲键盘，则等普通键全部松开且键盘空闲达到设置阈值，再切回指定输入法。

如果等待期间再次按下触发键，旧的切回任务会取消，避免连续语音输入时被提前切走。

若再次按下的事件被豆包吞掉，到期时仍可见的语音浮层会阻止切回；检测到真实松开后重新计时。如果松开事件也缺失，则从浮层消失后等待完整的延迟再切回。

键盘空闲阈值默认 1.5 秒，可在设置中调整为 0.1～300 秒。普通按键的按下、松开和长按重复都会更新活动时间；豆包等进程模拟的按键不计入。键盘保护只等待尚未满足的空闲时间，不会重新等待整轮切回延迟。若用户主动切到其他输入法，本轮自动切回会取消。

键盘保护依据按键活动，不检测拼音候选文字是否已上屏；停止按键超过阈值后仍会切回，选词或思考期间可按需调大阈值。

## 主要功能

- 自定义触发键，并与豆包的全局语音快捷键配合使用。
- 选择切回的输入法，默认优先选择微信 / WeChat / Weixin 输入法。
- 松开后的切回延迟可设置为 0～300 秒（最长 5 分钟）。
- 切回前等待键盘空闲，阈值默认为 1.5 秒，可设置为 0.1～300 秒。
- 菜单栏设置、启停开关和登录后自动启动。
- 显示辅助功能权限和监听状态，提供诊断日志入口。
- 在按键仍按住、已经切到豆包但语音浮层未出现时，做一次条件式按键补发，改善语音未启动的情况。

## 环境与构建

- macOS 13 或更新版本。
- 已安装并启用豆包输入法及需要切回的目标输入法。
- Xcode Command Line Tools；使用 Swift 和系统框架，无第三方包依赖。

在项目目录执行：

```bash
./scripts/build_app.sh
open "outputs/按住切换输入法.app"
```

脚本同时生成 `outputs/InputHoldSwitcher-macOS.zip`。应用和压缩包是构建产物，源码仓库中不附带这些文件。

脚本优先使用本机已有的 `InputHoldSwitcher Local Code Signing` 证书，也支持指定自己的稳定签名身份：

```bash
CODESIGN_IDENTITY="你的代码签名证书名称" ./scripts/build_app.sh
```

没有证书时，当前脚本会使用 ad-hoc 签名。希望更新后保持辅助功能授权稳定时，应持续使用同一个证书、Bundle ID `com.local.InputHoldSwitcher` 和安装位置。

## 首次设置

1. 在豆包输入法中开启“全局唤起语音”，把长按快捷键设为左 Control，或与本工具录制的触发键保持一致。
2. 启动工具，在“系统设置 → 隐私与安全性 → 辅助功能”中授权，然后重新启动工具。
3. 打开菜单栏设置，选择切回的输入法、松开后的延迟和键盘空闲阈值。
4. 开启“启用松开后自动切回”，按住触发键说话，松开后检查是否切回。
5. 按需开启开机自动启动。

## 常见问题

**列表里没有目标输入法？** 到“系统设置 → 键盘 → 文本输入 → 编辑”添加并启用它，再点击“刷新输入法列表”。

**松开后没有切回？** 检查启用开关、辅助功能权限和触发键设置。两边的快捷键应一致，目标输入法也必须保持启用。

**语音结束后切回太快？** 增大松开延迟，给豆包留出完成识别的时间。

**更新后要求重新授权？** 检查是否换了签名证书、应用标识或安装路径；ad-hoc 签名更新可能被系统识别为新的代码身份。

## 数据与诊断

工具通过只读键盘监听观察触发键，不拦截原始按键；必要的补发只用于语音启动兜底。设置保存在本机 `UserDefaults` 中，工具本身不联网、不记录输入文字。豆包语音识别的数据处理由豆包输入法负责。

菜单栏“打开诊断日志”对应 `~/Library/Logs/InputHoldSwitcher.log`，记录按键码、输入法 ID、权限和切换结果。

主实现位于 [main.swift](Sources/InputHoldSwitcher/main.swift)，打包入口为 [build_app.sh](scripts/build_app.sh)。
